## 2. 챕터별 공부할 내용 & 포인트

### 2-1. 이벤트 처리 ★★★

**개념**
- 이벤트: 사용자가 앱에 보내는 신호(터치, 키 입력 등) 또는 구성요소 간 신호(위치 변경 등)
- 종류: 터치 / 키 입력 / 포커스 변경 / 화면 방향 변경 / 제스처
- 이벤트 소스: 이벤트가 발생한 객체
- 이벤트 구동(event driven) 프로그래밍: 프로그램 실행이 이벤트 발생에 의해 결정되는 방식 (GUI 앱)
- **이벤트 콜백 메소드**: 이벤트 발생 시 시스템이 자동 호출, 오버라이딩해서 사용
- **이벤트 리스너**: 이벤트를 처리하는 객체, **인터페이스**로 정의되어 있음
- 리스너 처리 절차: (1) 리스너 구현 클래스 정의 + 처리 메소드 구현 → (2) 객체 생성 → (3) 뷰에 등록 → 이벤트 발생 시 자동 호출

**콜백/리스너 시그니처 (수기 출제 1순위)**

| 구분 | 이름 | 메소드 시그니처 |
|---|---|---|
| 콜백 | 키 누름 | `boolean onKeyDown(int keyCode, KeyEvent event)` |
| 콜백 | 키 뗌 | `boolean onKeyUp(int keyCode, KeyEvent event)` |
| 콜백 | 화면 터치 | `boolean onTouchEvent(MotionEvent event)` |
| 리스너 | `View.OnClickListener` | `void onClick(View v)` |
| 리스너 | `View.OnTouchListener` | `boolean onTouch(View v, MotionEvent event)` |
| 리스너 | `View.OnKeyListener` | `boolean onKey(View v, int keyCode, KeyEvent event)` |
| 리스너 | `View.OnFocusChangeListener` | `void onFocusChange(View v, boolean hasFocus)` |
| 리스너 | `CompoundButton.OnCheckedChangeListener` (CheckBox, Switch, ToggleButton) | 등록: `setOnCheckedChangeListener(listener)` |
| 리스너 | `RadioGroup.OnCheckedChangeListener` | **RadioGroup**에 `setOnCheckedChangeListener()` 등록 |
| 리스너 | `RatingBar.OnRatingBarChangeListener` | 등록: `setOnRatingBarChangeListener(listener)` |
| 리스너 | `AdapterView.OnItemSelectedListener` (Spinner) | `onItemSelected(parent: AdapterView<*>?, view: View?, position: Int, id: Long)`, `onNothingSelected(parent: AdapterView<*>?)` |
| 리스너 | `AdapterView.OnItemClickListener` (ListView) | 등록: `setOnItemClickListener()` |
| 리스너 | `NavigationView.OnNavigationItemSelectedListener` | 등록: `setNavigationItemSelectedListener(listener)` |

**클릭 리스너 구현 4가지 방법 (★★)**
1. 이름 있는 클래스로 `View.OnClickListener` 구현 → 객체 생성 → 등록
2. 익명 클래스로 구현 후 등록 (`object : View.OnClickListener { override fun onClick(v: View?) {...} }`)
3. 익명 클래스 구현과 동시에 생성/등록, 또는 **SAM 기법(람다)** `btn.setOnClickListener { ... }`
4. Activity가 리스너 인터페이스를 상속(implements)하고 `onClick` 재정의 → 등록 시 `this`

```kotlin
// 롱클릭: 처리 완료를 알리기 위해 true 반환 (AA_SQLite 완성본)
root.setOnLongClickListener {
    onItemLongClick(item)
    return@setOnLongClickListener true
}
```

**Toast & Log**
- `Toast.makeText(context, msg, duration).show()` : duration = `Toast.LENGTH_SHORT / LENGTH_LONG`. **show()를 빼먹지 말 것**
- Toast는 포커스를 받지 않고, 앱 화면이 사라져도 그대로 표시됨
- `Log.v / i / d / w / e (Tag, Message)` → Logcat 창에 출력 (v 상세, i 정보, d 디버그, w 경고, e 오류)

**기타 위젯 xml 속성**

| 위젯 | 속성 |
|---|---|
| ProgressBar | `style`(바/원 형태), `max`, `progress`, `secondaryProgress`, 메소드 `setProgress()` |
| RatingBar | `numStars`(별 개수), `rating`(초깃값), `stepSize`(한 번에 채워지는 양), 프로퍼티 `rating` |
| Switch/ToggleButton | 체크박스와 같은 속성/메소드, `checked` true/false |

**(4) Navigation Drawer (★★★)**
- 구성 요소: DrawerLayout / NavigationView / NavHostFragment / AppBarConfiguration / NavController / Navigation Graph
  - **NavHostFragment**: 화면 전환 시 화면을 보여주는 컨테이너
  - **NavController**: 프래그먼트 간 화면 전환을 관리(주관)하는 객체
  - **AppBarConfiguration**: 앱바 왼쪽 상단 탐색 버튼 동작 관리
  - **Navigation Graph**: 내비게이션에 쓰이는 프래그먼트들을 모아 관리하는 xml
- **구현 절차 5단계**: (1) 화면별 layout + Fragment 클래스 → (2) Navigation Graph 생성 → (3) Navigation 메뉴 설정 → (4) DrawerLayout+NavigationView로 메인 레이아웃 + Nav Host 설정 → (5) AppBarConfiguration과 NavigationUI로 탐색 동작 설정
- DrawerLayout: 보통 루트, **자식 2개** (첫째: 액티비티 화면, 둘째: 스와이프하면 보이는 서랍), `android:layout_gravity`로 열리는 방향

### 2-3. RecyclerView / 어댑터 뷰 ★★★

- AdapterView: 뷰에 데이터를 직접 저장하지 않고 **Adapter**라는 중간 매개체로 필요할 때 가져다 쓰는 뷰 (ListView, RecyclerView, Spinner, GridView)
- Adapter 종류: ArrayAdapter, SimpleAdapter, BaseAdapter/RecyclerView.Adapter 상속 Custom Adapter
- **RecyclerView 구성 요소**: **ViewHolder(필수)**, **Adapter(필수)**, **LayoutManager(필수)**, ItemDecoration(옵션)
- 구현 순서: (1) 액티비티 레이아웃에 RecyclerView → (2) 항목 레이아웃(item_xxx.xml) → (3) ViewHolder (`RecyclerView.ViewHolder` 상속) → (4) Adapter → (5) 레이아웃매니저/어댑터/데코레이션 연동

| Adapter 재정의 메소드 | 호출 시점 | 시그니처 |
|---|---|---|
| `getItemCount()` | 항목 개수 판단 | `override fun getItemCount(): Int` |
| `onCreateViewHolder()` | 뷰홀더 준비 | `override fun onCreateViewHolder(parent: ViewGroup, viewType: Int): ItemViewHolder` |
| `onBindViewHolder()` | 뷰홀더 뷰에 데이터 출력 | `override fun onBindViewHolder(holder: ItemViewHolder, position: Int)` |

**(2) Contract 클래스 + SQLiteOpenHelper**
- Contract: 테이블 이름, 컬럼 이름, SQL 문장 상수를 한 곳에 모음 → 구조/이름 변경 시 수정 최소화
- SQLiteOpenHelper 장점: 파일 경로 직접 지정 불필요, **버전 관리** 기능
- `getWritableDatabase()`(추가/수정/삭제용), `getReadableDatabase()`(조회용) → Kotlin `writableDatabase / readableDatabase`
- 사용 순서: (1) 상속해 helper 정의 → (2) helper 객체 생성 → (3) SQLiteDatabase 얻기 → (4) 질의 처리 → (5) helper close

```kotlin
class DBHelper(context: Context?) : SQLiteOpenHelper(context, DB_FILE, null, DB_VERSION) {
    override fun onCreate(db: SQLiteDatabase) {                 // helper가 준비되면 호출
        db.execSQL(DBContract.SQL_CREATE_TABLE)
    }
    override fun onUpgrade(db: SQLiteDatabase, oldVersion: Int, newVersion: Int) {  // 버전 변경 시
        db.execSQL(DBContract.SQL_DROP_TABLE)
        onCreate(db)
    }
    companion object {
        const val DB_FILE = "flea_t.db"
        const val DB_VERSION = 1
    }
}
dbHelper = DBHelper(baseContext)
val db = dbHelper.readableDatabase
override fun onDestroy() { if (dbHelper != null) dbHelper.close(); super.onDestroy() }
```

**(3) Room (★★★ 실습 앱이 Room 사용)**
- ORM: DB 테이블/레코드를 객체로 매핑. 장점: 컴파일 시 SQL 유효성 검사, 구조 변경 반영 용이, 객체 매핑 용이
- 구성요소: **Database**(DB 생성, 버전 관리), **Dao**(DB 작업을 메소드로 정의, 보통 interface), **Entity**(테이블 구조 = 레코드)
- 개발 방법 7단계: 라이브러리 추가(Sync) → Entity → Dao → Database 클래스 → Database 객체 생성 → Dao 객체 생성 → 추가/변경/삭제/조회
- 라이브러리(슬라이드): room-runtime, room-ktx는 implementation, room-compiler는 annotationProcessor/kapt (libs.versions.toml + build.gradle 또는 Project Structure > Dependencies)

| 어노테이션 | 의미 |
|---|---|
| `@Entity(tableName = "LOSTFOUND_T")` | 엔티티(테이블), 기본은 클래스 이름이 테이블 이름 |
| `@PrimaryKey` / `@PrimaryKey(autoGenerate = true)` | 기본키 / 자동 증가 |
| `@ColumnInfo(name = "partner_name")` | 컬럼 이름을 변수명과 다르게 |
| `@Dao` | Dao 클래스 |
| `@Insert` / `@Update` / `@Delete` | 추가 / 변경 / 삭제 메소드 |
| `@Query("SELECT ...")` | 조회 등 SQL 메소드, 파라미터는 `:이름` |
| `@Database(entities = arrayOf(X::class), version = 1, exportSchema = false)` | RoomDatabase 상속 DB 클래스 |

```kotlin
@Dao
interface LostFoundDao {
    @Query("SELECT * from LOSTFOUND_T ORDER BY createdAt DESC")
    fun getAll(): List<LostFoundItem>
    @Query("Select * from lostfound_t where id = :itemId")
    fun foundItemById(itemId: Long): LostFoundItem?
    @Insert fun insert(item: LostFoundItem)
    @Update fun update(item: LostFoundItem)
    @Delete fun delete(item: LostFoundItem)
}
@Database(entities = arrayOf(LostFoundItem::class), version = 1, exportSchema = false)
abstract class LostFoundDatabase : RoomDatabase() {
    abstract fun lostFoundDao(): LostFoundDao
}
// 객체 생성
database = Room.databaseBuilder(applicationContext, LostFoundDatabase::class.java, "lostfound_t").build()
dao = database.lostFoundDao()
```
